Developer documentation

Deploy the MCP server on Vercel.

Hosted mode uses a Next.js Node Function on Vercel, Streamable HTTP, per-user OAuth with PKCE, and Upstash Redis to store revocable grants. Local stdio remains available for private repositories and local build folders.

Production endpoint is published after Vercel project setup

01 · Architecture

Keep each user's Cloudflare access separate.

Hosted · Vercel

Users connect to /api/mcp, authorize with OAuth, then enter their own Cloudflare Account ID and scoped token. Their credential is encrypted before Redis storage.

Local · stdio

Runs on the user's computer, reads built files such as ./dist, and uses credentials from the ignored local .env.

Hosted Vercel mode does not use the maintainer's CLOUDFLARE_API_TOKEN or CLOUDFLARE_ACCOUNT_ID from .env. A shared operator token would give every connector access to the same Cloudflare account, so hosted requests use OAuth per-user credentials instead.

02 · Hosted deployment

Deploy the repository to Vercel.

  1. Import the GitHub repository hoangtrietdev/cloudflare-mcp as a new Vercel project. Use the project root, framework Next.js, and Node.js 22.
  2. From Vercel Marketplace, add and connect an Upstash Redis database. It supplies UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN to the Vercel project.
  3. Generate a separate encryption key and add it under Vercel → Project Settings → Environment Variables → Production. Changes require a new deployment.
  4. Deploy the production branch and wait for the build. The MCP endpoint is https://<project-name>.vercel.app/api/mcp.
  5. After the project name is known, replace the endpoint placeholder in public/index.html and publish the updated landing page.
GENERATE A 32-BYTE CREDENTIAL ENCRYPTION KEY
openssl rand -base64 32

# Set the output as Vercel env var:
MCP_CREDENTIALS_ENCRYPTION_KEY

GitHub Actions does not need Cloudflare credentials for this deployment. Vercel Git integration builds from the repository; project env supplies Redis and the encryption key.

03 · OAuth & credential handling

Authorization code, PKCE, encrypted storage.

  • Implements protected-resource and authorization-server metadata, dynamic public-client registration, authorization code + PKCE S256, refresh-token rotation, and revocation.
  • Cloudflare API Tokens are verified over HTTPS, then AES-256-GCM encrypted using MCP_CREDENTIALS_ENCRYPTION_KEY before storage in Upstash Redis.
  • Access tokens expire after 1 hour. Refresh grants expire after 30 days; refresh rotates the token. Revocation removes token indexes and the encrypted grant.
  • Cloudflare Pages Edit is required to deploy. Zone Read and DNS Edit are needed only for automatic DNS changes.
  • Keep the encryption key stable and private. Rotating it prevents decryption of existing grants; users must reconnect.

Vercel environment variables are encrypted at rest and apply to new deployments after changes. GitHub Actions secrets and Vercel runtime environment variables are separate stores; this project does not copy the global local .env Cloudflare credential into GitHub.

04 · MCP tools

Deploy prebuilt static output from GitHub.

  • deploy_to_cloudflare_pages: public GitHub repo, branch, output directory, SPA fallback option, and Cloudflare project name.
  • attach_custom_domain: attach an owned domain and create a CNAME if the user's authorized Cloudflare account contains the DNS zone and no record conflicts.
  • list_deployments: recent statuses, URLs, and custom-domain bindings.
  • Hosted mode never runs repository scripts. The GitHub repository must already contain the build output and index.html.
  • Limits: 20 MiB compressed archive, 50 MiB expanded output, 10 MiB per asset, and 20,000 files. Private GitHub repositories are not supported in hosted mode.
05 · Local stdio

Run against local files or private source.

LOCAL SETUP
git clone https://github.com/hoangtrietdev/cloudflare-mcp.git
cd cloudflare-mcp
npm ci
cp .env.example .env
# Set CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID
npm run build

Use the config samples in examples/configs/; they launch scripts/start-local.mjs. Build the app first, then pass dir_path: ./dist. Set spa_mode: true for React/Vite client-side routes.

06 · CI & reference docs

Validate the local package and Vercel build.

CHECKS
npm ci
npm run typecheck
npm test
npm run build:vercel

GitHub Actions checks the stdio package on Node 18, 20, and 22 and builds the Next.js app on Node 22. Vercel deploys commits from the configured Git branch.
