Hướng dẫn từng bước · tiếng Việt

Từ tài khoản Cloudflare đến lần deploy đầu tiên.

Làm theo hướng dẫn này để tạo token đúng quyền, kết nối MCP vào trợ lý lập trình, rồi yêu cầu deploy bằng ngôn ngữ tự nhiên.

01

Tạo tài khoản Cloudflare

  1. Mở trang đăng ký Cloudflare, nhập email và mật khẩu, sau đó xác minh email nếu được yêu cầu.
  2. Đăng nhập vào Dashboard. Bạn có thể dùng Cloudflare Pages với địa chỉ miễn phí ten-du-an.pages.dev mà chưa cần mua hoặc thêm domain riêng.
  3. Không cần chuyển DNS hay thêm website/domain để thử deploy lần đầu.

Tên project phải viết thường, có thể gồm số và dấu gạch ngang, ví dụ mystoreabc.

Đăng ký Cloudflare ↗
02

Lấy Account ID

  1. Trong Dashboard, mở Workers & Pages; tìm khu vực Account Details.
  2. Bấm nút sao chép cạnh Account ID. Đây là mã tài khoản Cloudflare, không phải Zone ID hay email.
  3. Cách khác: dùng ô tìm kiếm Dashboard, gõ Copy account ID rồi chọn kết quả.

Nếu tài khoản có nhiều account, chọn đúng account dùng để deploy.

Tài liệu tìm Account ID ↗
03

Tạo API Token với quyền tối thiểu cần thiết

Token cho phép MCP gọi Cloudflare API thay mặt bạn. Tạo token riêng thay vì dùng Global API Key; secret chỉ hiện một lần.

  1. Vào Manage Account → API Tokens (hoặc My Profile → API Tokens), chọn Create Token → Create Custom Token.
  2. Đặt tên dễ nhận biết, ví dụ mcp-cloud-deploy-local.
  3. Thêm quyền và phạm vi tài nguyên bên dưới. Chỉ thêm DNS nếu muốn MCP tự tạo record cho domain riêng.

  1. Kiểm tra summary quyền và account/zone, rồi bấm Create Token.
  2. Sao chép token ngay và lưu tạm trong trình quản lý mật khẩu. Không dán token vào chat, GitHub, ảnh chụp màn hình hay file cấu hình MCP.

Chỉ dùng pages.dev? Chỉ cần Cloudflare Pages: Edit; bỏ qua quyền Zone. DNS ở nhà cung cấp khác? MCP sẽ đưa hướng dẫn CNAME để bạn tự cấu hình, không cần cấp quyền DNS tự động.

04

Lưu credentials trong file .env cục bộ

Mở Terminal và chạy lệnh cài đặt:

git clone https://github.com/hoangtrietdev/cloudflare-mcp.git cd cloudflare-mcp npm ci cp .env.example .env

Mở .env bằng editor và thay giá trị mẫu:

CLOUDFLARE_API_TOKEN=token_ban_vua_tao CLOUDFLARE_ACCOUNT_ID=account_id_cua_ban

Sau đó chạy npm run build. File .env đã được Git ignore; không commit file này.

Đừng đặt token trong JSON của Codex/VS Code/Claude/JetBrains. MCP đọc credentials local từ .env.

05

Kết nối Codex, VS Code, Claude hoặc JetBrains

  1. Ở bảng cấu hình MCP bên dưới, chọn ứng dụng và nhập đường dẫn tuyệt đối đến repo vừa clone.
  2. Bấm Copy config, dán vào đúng file/cài đặt MCP được hiển thị rồi lưu.
  3. Khởi động lại ứng dụng hoặc reload MCP servers. Kiểm tra có tools deploy_to_cloudflare_pages, attach_custom_domain và list_deployments.

Ví dụ đường dẫn: /Users/ten-ban/cloudflare-mcp trên macOS hoặc C:\Users\ten-ban\cloudflare-mcp trên Windows.

Server không khởi chạy? Kiểm tra đường dẫn, Node.js 18+, file .env, rồi khởi động lại client.

06

Deploy website tĩnh hoặc React

  1. Build website bằng lệnh quen thuộc, ví dụ npm run build. Vite thường xuất ra dist; CRA thường là build.
  2. Yêu cầu: Deploy website của tôi tên mystoreabc từ ./dist. Tôi chưa có domain.
  3. MCP kiểm tra thư mục có index.html, tải assets lên Pages và trả URL như https://mystoreabc.pages.dev.
  4. Với React SPA có client-side routing, nói rõ “đây là React SPA, bật chế độ SPA”. Next.js SSR, API backend và Node server cần runtime phù hợp; static upload chỉ xuất bản output tĩnh.

Landing page nhiều ảnh/font/script vẫn deploy được: trỏ đúng thư mục build để giữ nguyên các đường dẫn assets tương đối.

07

Thêm domain riêng khi đã có domain

Đăng ký domain ở nhà cung cấp bất kỳ; chưa cần chuyển registrar sang Cloudflare. Sau đó yêu cầu: Gắn www.example.com vào project mystoreabc.

  • Nếu DNS zone nằm trong Cloudflare account và token có Zone Read + DNS Edit, MCP thêm domain và tạo CNAME trỏ tới mystoreabc.pages.dev.
  • Nếu DNS ở GoDaddy, Namecheap hoặc nơi khác, MCP trả chính xác hostname, loại record và target để bạn tự thêm trong DNS dashboard.
  • Domain gốc/apex (ví dụ example.com) cần zone được quản lý trên Cloudflare để cấu hình Pages trực tiếp. Subdomain thường dùng CNAME.

Cloudflare cấp SSL sau khi domain/DNS được xác minh và propagation hoàn tất; trạng thái có thể chưa sẵn sàng ngay lập tức.

08

Nếu gặp lỗi

  • 401 / 403: token sai/hết hạn hoặc thiếu Pages Edit; kiểm tra Account ID và resource scope.
  • Không tìm thấy project: kiểm tra account đang chọn; project mới có thể được tạo khi deploy nếu token cho phép.
  • Thiếu index.html: deploy nhầm thư mục source. Build trước rồi dùng output như dist/build.
  • Domain pending: xác nhận CNAME đúng target, không có record xung đột, rồi chờ DNS/SSL propagation.

Nếu nghi token bị lộ, thu hồi tại Cloudflare → API Tokens, tạo token mới và cập nhật file local .env.
